# PROG5121 POE Part 2: Sending Messages

Project Overview

This project is a Java application developed for the PROG5121 Portfolio of Evidence (POE), Part 2. It focuses on implementing a messaging system that allows users to create, validate, manage, and store messages.

The project demonstrates the use of object-oriented programming, input validation, message identification, message hashing, and automated testing.

Project Objectives

The main objectives of this project are to:

* Implement the message functionality required by the assignment.
* Validate message information before processing it.
* Generate message identifiers and message hashes.
* Manage message data using the provided Java classes.
* Test the application using automated unit tests.

Technologies Used

* Programming language: Java
* Build tool: Apache Maven
* Testing framework: JUnit
* Development environment: Visual Studio Code / GitHub Codespaces
* Data handling: JSON library included with the project

Project Structure

The Java project is located in the Registration/Registration directory.

The main files include:

* Registration.java — application entry point.
* Message.java — message-related functionality.
* MessageStorage.java — message storage functionality.
* Login.java — login-related functionality.
* pom.xml — Maven configuration and project dependencies.

The project also contains test classes for the login, message, and message-storage functionality.

How to Run the Project

1. Open the project in a Java-compatible development environment.
2. Ensure that Java and Apache Maven are installed or available in the environment.
3. Open a terminal in the directory containing pom.xml.
4. Run the following command to execute the automated tests:

mvn test

5. Review the test output and resolve any reported failures before considering the tests complete.

To run the application, use the appropriate run configuration for Registration.java in your Java development environment.

Testing

The project includes automated tests for different parts of the application, including login functionality, message functionality, and message storage.

The tests should be executed using Maven. Any failures must be investigated and corrected, and the tests should be run again to verify the changes.

Current status: Testing is in progress. The latest Maven run reported test failures, so the final test results must be confirmed after the issues have been resolved.

Conclusion

This project provides practical experience in Java programming, object-oriented design, input validation, message management, and unit testing. Testing and reviewing the application helps identify problems and improve the reliability of the final implementation.
